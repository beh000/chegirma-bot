# chegirma-bot

Telegram-бот — агрегатор скидок и акций для канала [@chegirma_official](https://t.me/chegirma_official).
Каждые 30 минут проверяет 10 сайтов, находит новые акции и публикует их в канал на русском и узбекском.

Публикуются только 3 категории: **еда**, **одежда**, **техника** (`utils/category.js`
→ `CATEGORIES`). Всё, что не удалось отнести к одной из них по ключевым словам
в названии (или явной категорией с сайта), не постится — фильтр стоит в
`index.js` → `normalizeDeal`.

Живёт на Railway: проект `chegirma-bot` в воркспейсе `beh000's Projects`,
сервис `chegirma-bot`, ветка `claude/chegirma-telegram-bot-4giu96`. Собирается
через `Dockerfile` (не Railpack/Nixpacks — см. ниже почему).

| **Makro** | ✅ публикует, когда есть акции | селекторы подтверждены и рабочие, но каталог не всегда отдаёт акции на `/promotions` — зависит от того, идёт ли сейчас распродажа |
| Texnomart | ⚠️ находит, но не публикует | 20 акций на странице есть, но ни на странице категории, ни на странице товара, ни в JSON API нет "старой" цены (проверено network-capture'ом) — процент скидки посчитать не из чего. Подтверждённый пробел в данных сайта, не баг парсера |
| Evos | ⚠️ находит, но не публикует | реальное меню и раздел "Aksiyalar" — на `evos.uz` (не `zakaz.evos.uz`, это просто страница-хаб со ссылками на Telegram-бот/приложения). | Korzinka | ❌ | за Cloudflare-челленджем (`<title>Один момент…</title>`) — не проходит ни обычный Playwright+stealth, ни Patchright (патчит CDP-утечки вроде `Runtime.enable`) — **нужен платный anti-detect/резидентные прокси**, см. ниже |
| Mediapark | ❌ | то же самое, тот же Cloudflare-челлендж |
| Asaxiy | ❌ | то же самое |

Три сайта из десяти реально работают до состояния "видит акцию → публикует"
(Uzum, Makro, и Evos/Texnomart при наличии данных на самом сайте). Tezz —
новый источник без антибота, но пока без подтверждённых на практике акций.
Ещё четыре (Korzinka/Mediapark/Asaxiy/AliExpress) упираются в антибот-защиту,
для которой бесплатных техник больше не осталось — см. "Почему часть сайтов
не работает" ниже. Публичные Telegram-каналы этих же магазинов (`t.me/s/…`)
проверены отдельно — Cloudflare там нет, но контент маркетинговый
(анонсы акций, розыгрыши), без структурированных пар цена-была/цена-стала,
так что под текущий формат поста не ложится напрямую.

## Установка и локальный запуск

```bash
npm install          # postinstall сам скачает Chromium для Playwright
cp .env.example .env   # вписать реальный BOT_TOKEN
npm start
```

Локально (без Docker) headless-браузер обычно работает из коробки на
Linux/macOS с уже установленными системными библиотеками — если Chromium не
запускается, см. `npx playwright install --with-deps chromium`.

## Переменные окружения

| Переменная  | Значение |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `CHANNEL_ID` | `@chegirma_official` |
| `INSPECT` | `1` — вместо обычного цикла один раз собирает диагностику по сайтам и логирует классы/цены, потом завершает процесс (см. ниже). Не задавать/`0` — обычная работа. |
| `INSPECT_BROWSER` | `1` — диагностика идёт через headless-браузер вместо обычного запроса. |
| `INSPECT_ONLY` | список имён сайтов через запятую (`Korzinka,Makro`) — сузить диагностику до конкретных сайтов. |
| `INSPECT_PRODUCT_URL` | доп. проверка конкретной страницы товара Texnomart (использовалось для поиска старой цены). |
| `INSPECT_NETWORK_URL` | открывает URL headless-браузером и логирует все JSON-ответы (XHR/fetch), которые сайт грузит сам — ищет скрытые API. |
| `INSPECT_TEXT_URL` | печатает в лог весь видимый текст страницы (`document.body.innerText`) — надёжнее скриншота, чтобы понять, что сайт вообще показывает (экран выбора города, заглушка и т.п.), без риска повредить данные при копировании. |
| `INSPECT_SCREENSHOT_URL` | печатает JPEG-скриншот страницы как base64 кусками по 1000 символов — последний резерв, если текстовые эвристики ничего не нашли. На практике оказался ненадёжным (ручная сборка из логов легко повреждается) — предпочитайте `INSPECT_TEXT_URL`. |
| `INSPECT_JSON_URL` + `INSPECT_JSON_PATH` | достаёт `__NEXT_DATA__` с отрендеренной страницы и печатает поддерево по точечному пути (`props.pageProps.sale`) — чтобы увидеть точную схему полей конкретного JSON-блока, не выкачивая всё целиком. |

`.env` в git не коммитится (см. `.gitignore`) — токен бота это секрет. На Railway
переменные задаются в Settings → Variables проекта, а не в файле.

**Бот должен быть администратором канала @chegirma_official** с правом публикации
постов — иначе `sendMessage`/`sendPhoto` будет падать с ошибкой прав.

## Деплой на Railway

Собирается через **Dockerfile**, не через Railpack/Nixpacks (дефолтный
билдер Railway). Причина: боту нужен headless Chromium (Playwright) для
части сайтов, а `playwright install --with-deps chromium` под Railpack не
докатывает системные библиотеки в финальный образ (проверено вживую —
Chromium падал с `error while loading shared libraries: libglib-2.0.so.0`).
`Dockerfile` берёт официальный образ `mcr.microsoft.com/playwright:v1.63.0-noble`
ради его системных библиотек для Chromium — сам браузер бот запускает через
**Patchright** (форк Playwright с патчами CDP-утечек против антибота, см.
"Почему часть сайтов не работает"), который ставит себе Chrome сам через
`postinstall`. Версия тега в `Dockerfile` должна совпадать с версией пакета
`"patchright"` в `package.json` (обе следуют номерам версий playwright) —
если обновляете один, обновите и другой.

Builder сервиса на Railway выставлен явно (`build.builder = DOCKERFILE`,
`dockerfilePath = Dockerfile`) через Railway API — простого наличия
`Dockerfile` в репозитории недостаточно, если до этого билдер уже был задан
иначе.

**Persistent Volume**: к сервису подключён Railway Volume, смонтированный на
`/app/data` — там хранится `posted.json` (дедупликация). Без него история
публикаций обнулялась бы при каждом редеплое, и часть акций уходила бы в
канал повторно. Volume уже создан и подключён (`chegirma-data`), трогать не
нужно.

## Как чинить сайт, если он перестал публиковать (диагностический режим)

Раз в CSS-селекторы иногда меняются, а у части сайтов бывает антибот-защита —
вместо того чтобы гадать вслепую, можно временно включить диагностику прямо
на Railway и посмотреть на реальную вёрстку через логи:

1. В Variables поставить `INSPECT=1` (и `INSPECT_BROWSER=1`, если сайт грузится
   через headless-браузер — см. таблицу выше и `parsers/*.js`, какие уже на
   браузере). Redeploy запустится автоматически.
2. Открыть Deploy Logs — там будут: размер полученного HTML, найденные
   `__NEXT_DATA__`/JSON-LD, и элементы, похожие на цену, вместе с их
   CSS-классами и цепочкой родителей (`utils/inspect.js`).
3. Поправить `SELECTORS`/логику в соответствующем `parsers/<site>.js` по этим
   реальным данным.
4. Вернуть `INSPECT` в `0` (или удалить переменную) — бот снова заработает по
   обычному крону.

`INSPECT_ONLY=Korzinka,Makro` сужает прогон до конкретных сайтов, чтобы не
гонять все девять ради одного.

## Почему часть сайтов не работает — разбор по типам защиты

- **Cloudflare-челлендж** (Korzinka, Mediapark, Asaxiy): страница отвечает
  `<title>Один момент…</title>` с `Content-Security-Policy: default-src
  'none'` — это классический JS-челлендж Cloudflare перед настоящей
  страницей. Испробованы два разных бесплатных подхода, оба не прошли:
  сначала playwright-extra + puppeteer-extra-plugin-stealth (маскирует
  JS-признаки headless-браузера), потом **Patchright** — форк Playwright,
  который патчит сами CDP-утечки (`Runtime.enable` и т.п.), а не
  JS-поверхность. Оба дали идентичный результат — страница-челлендж без
  редиректа на реальный контент. Это указывает на блокировку по репутации
  IP (датацентровский IP Railway), а не только на фингерпринт браузера —
  **дальше нужны платные anti-detect/резидентные прокси** (или официальный
  API/фид от магазина, если такой есть).
- **AliExpress**: тот же класс защиты, тот же результат с Patchright —
  тоже упирается в платный anti-detect.
- **Данные не в HTML/JSON, а в сериализованном формате фреймворка**
  (Dominos, Nuxt `__NUXT_DATA__`): headless-рендер должен решать эту
  проблему (просто взять уже отрисованный DOM), но каталог всё равно пуст —
  либо на `/stocks` сейчас правда нет активных акций (что подтверждает и
  независимый веб-поиск), либо там та же Cloudflare-защита в более мягкой
  форме.
- **Данных просто нет на сайте** (Texnomart, Evos): у Texnomart категория
  "акции" содержит 20 реальных товаров, но ни на карточке в каталоге, ни на
  странице товара, ни в его собственном JSON API (проверено
  `INSPECT_NETWORK_URL`) нет "старой" цены — только текущая. У Evos
  аналогично: `zakaz.evos.uz` (изначально угаданный URL) оказался просто
  страницей со ссылками на Telegram-бот/приложения без какого-либо меню —
  настоящее меню нашлось на `evos.uz`, но и там, и в разделе "Aksiyalar", и
  во всём каталоге JSON API (`__NEXT_DATA__.props.pageProps.sale` /
  `.getMenu.data.menu`) у каждого товара только одно поле цены (`dprice`),
  сравнительной "было/стало" цены нет вообще. Без неё не из чего посчитать
  `%`, а шаблон поста его требует. Это не защита от ботов, а особенность
  того, как эти два сайта показывают свои акции — код обоих парсеров уже
  переписан на прямое чтение их реальных JSON-структур, так что если сайт
  когда-нибудь добавит поле старой цены, публикации заработают сами, без
  правок кода.

## Архитектура

```
chegirma-bot/
├── index.js              # оркестратор: cron каждые 30 мин, обход всех сайтов, INSPECT-режим
├── bot.js                 # Telegram Bot API напрямую (без node-telegram-bot-api, см. ниже)
├── Dockerfile              # официальный образ Playwright — см. "Деплой на Railway"
├── parsers/                # по одному файлу на сайт, все экспортируют parse()
├── utils/
│   ├── http.js             # axios + cookie jar + браузерные заголовки, для сайтов без защиты
│   ├── browser.js           # headless Chromium (Playwright) — для WAF/SPA-сайтов
│   ├── inspect.js            # диагностика вживую (см. "Как чинить сайт")
│   ├── category.js            # эмодзи/переводы категорий, детект по ключевым словам
│   ├── storage.js              # data/posted.json — дедупликация, хранит последние 1000
│   └── parserHelpers.js         # общие хелперы парсинга (цены, JSON-LD, __NEXT_DATA__...)
├── data/posted.json          # живёт на Railway Volume, не теряется между деплоями
└── .env.example
```

### Почему без `node-telegram-bot-api`

Текущий npm-пакет с этим именем — не привычная классическая библиотека, а
другой переписанный клиент с несовместимым API (ESM-only, другая структура
экспортов). Старая ветка 0.x тянет депрекейтед `request` с критическими CVE
(form-data/SSRF). Вместо этого `bot.js` вызывает Telegram Bot API напрямую
через axios — лишней зависимости не нужно.

### Фото в постах

Telegram по умолчанию сам скачивает фото по присланному URL — но у части
сайтов (замечено на uzum.uz) на CDN картинок настроена хотлинк-защита, и
Telegram получает отказ (`400: failed to get HTTP URL content`). Поэтому
`bot.js` скачивает картинку сам (теми же браузерными заголовками, что и
парсер) и грузит её в Telegram файлом (multipart, нативный `FormData`/`Blob`
Node.js, без доп. зависимостей) — так фото проходит стабильно.

При частой публикации (много новых акций за один цикл) Telegram может
ответить `429 Too Many Requests` — `callTelegram` в этом случае ждёт ровно
столько, сколько просит сам Telegram (`retry_after`), и повторяет запрос, а
не просто бросает пост.

## Идеи на будущее (не реализовано)

- **Платный anti-detect/резидентные прокси для Cloudflare-сайтов**
  (Korzinka, Mediapark, Asaxiy, AliExpress) — самое дорогое и самое ценное
  следующее улучшение: разблокирует сразу 4 из 9 источников. Два бесплатных
  подхода (stealth-плагин, затем Patchright) уже испробованы и не прошли —
  дальше без платного сервиса (резидентные прокси, 2captcha/FlareSolverr и
  т.п.) не обойтись. Это осознанный, не автоматизируемый бесплатно шаг.
- **Официальные API вместо HTML-скрейпинга** там, где они есть — надёжнее
  и не ломается при редизайне сайта.
- **Health-алерты**: если сайт N раз подряд возвращает 0 акций — слать
  уведомление в приватный чат админу, чтобы не мониторить логи вручную.
- **/stats** — админ-команда в личке боту с числом постов за сегодня/неделю
  по каждому магазину.
- Переезд `data/posted.json` на MongoDB, если канал вырастет и понадобится
  более 1000 записей истории или несколько инстансов бота одновременно
  (сейчас это не нужно — Volume уже решает проблему персистентности).
