# chegirma-bot

Telegram-бот — агрегатор скидок и акций для канала [@chegirma_official](https://t.me/chegirma_official).
Каждые 30 минут проверяет 10 сайтов, находит новые акции и публикует их в канал на русском и узбекском.

## Установка и локальный запуск

```bash
npm install
cp .env.example .env   # вписать реальный BOT_TOKEN
npm start
```

## Переменные окружения

| Переменная  | Значение |
|---|---|
| `BOT_TOKEN` | токен бота от @BotFather |
| `CHANNEL_ID` | `@chegirma_official` |

`.env` в git не коммитится (см. `.gitignore`) — токен бота это секрет. На Railway
переменные задаются в Settings → Variables проекта, а не в файле.

**Бот должен быть администратором канала @chegirma_official** с правом публикации
постов — иначе `sendMessage`/`sendPhoto` будет падать с ошибкой прав.

## Деплой на Railway

1. Залить репозиторий в Railway (или подключить GitHub-репо).
2. В Settings → Variables добавить `BOT_TOKEN` и `CHANNEL_ID`.
3. Railway сам увидит `Procfile` (`web: node index.js`) и `"start"` в `package.json`.
4. **Важно про хранение `data/posted.json`**: без подключённого Volume диск
   контейнера сбрасывается при каждом новом деплое — история опубликованных
   акций обнулится, и часть акций может уйти в канал повторно один раз после
   передеплоя. Рекомендуется подключить Railway Volume и примонтировать его
   на каталог `data/` (Settings → Volumes), тогда `posted.json` переживёт
   передеплои.

## ⚠️ Главное ограничение этой версии — селекторы не проверены вживую

Эта версия бота была написана в изолированной песочнице **без доступа к
интернету** (политика организации блокирует выход на korzinka.uz, uzum.uz и
т.д. на уровне egress-прокси) — поэтому я не мог открыть ни один из 10 сайтов
и посмотреть на их реальную вёрстку.

Архитектура спроектирована так, чтобы это было легко исправить:

- Все CSS-селекторы вынесены в один объект `SELECTORS` вверху каждого файла
  в `parsers/*.js` — их видно и можно менять, не трогая остальную логику.
- Для сайтов на React/Next.js (`uzum.uz`, `texnomart.uz` и т.п.) парсер сперва
  пробует достать данные из встроенного JSON (`__NEXT_DATA__` / JSON-LD) —
  это надёжнее, чем гадать CSS-классы, но схема полей там тоже угадана
  эвристически (`utils/parserHelpers.js` → `guessProduct`).
- Каждый цикл подробно логирует: какой сайт проверяется, сколько карточек
  найдено. После первого реального запуска на Railway в логах сразу будет
  видно, какие сайты отдают 0 акций — значит там нужно поправить селектор.

**Как поправить парсер конкретного сайта:**
1. Смотрим лог `[Название] Найдено акций на странице: 0`.
2. Открываем `PROMO_URL` этого сайта в браузере → DevTools → ищем блок с
   карточкой товара → копируем реальные CSS-классы.
3. Вписываем их в `SELECTORS` в соответствующем файле `parsers/*.js`.

Отдельно про **AliExpress**: сайт активно защищается от ботов (антибот/капча
на CDN), простой запрос через axios почти наверняка получит заглушку вместо
каталога — это ограничение сайта, а не баг. Для реальной интеграции нужен
официальный AliExpress Affiliate API либо headless-браузер (Playwright) —
дороже по ресурсам и сложнее в обслуживании.

Про **Hamkorbank**: их акции — это обычно "кэшбэк X% картой", без пары
"старая цена → новая цена" у конкретного товара. Раз шаблон поста требует обе
цены, такие предложения сейчас отфильтровываются намеренно (см. комментарий в
`parsers/hamkorbank.js`). Если нужно публиковать кэшбэки без цены — это
отдельный формат поста, нужно решить вместе.

## Структура проекта

```
chegirma-bot/
├── index.js              # оркестратор: cron каждые 30 мин, обход всех сайтов
├── bot.js                 # Telegram-бот, формирование поста, отправка
├── parsers/                # по одному файлу на сайт, все экспортируют parse()
├── utils/
│   ├── http.js             # axios с User-Agent, ретраями
│   ├── category.js          # эмодзи/переводы категорий, детект по ключевым словам
│   ├── storage.js            # data/posted.json — дедупликация, хранит последние 1000
│   └── parserHelpers.js       # общие хелперы парсинга (цены, JSON-LD, __NEXT_DATA__...)
├── data/posted.json
├── Procfile
└── .env.example
```

## Идеи на будущее (не реализовано, для обсуждения)

- **Health-алерты**: если сайт N раз подряд возвращает 0 акций — слать
  уведомление в приватный чат админу, чтобы не мониторить логи вручную.
- **Playwright для JS-тяжёлых сайтов** (в первую очередь AliExpress) — точнее,
  но заметно дороже по ресурсам, разумно включать только для проблемных сайтов.
- **Официальные API вместо HTML-скрейпинга** там, где они есть — надёжнее
  и не ломается при редизайне сайта.
- **/stats** — админ-команда в личке боту с числом постов за сегодня/неделю
  по каждому магазину.
- Переезд `data/posted.json` на MongoDB, если канал вырастет и понадобится
  более 1000 записей истории или несколько инстансов бота одновременно.
